# 🏃 ランナーズ・ライブ（試作版）

トレイルラン・マラソン大会で、クラブの仲間の **現在地・状態・チャット・写真** を地図で共有するWebアプリです。
Firebase（無料のSparkプラン）で動きます。メンバーは **リンクを開いて名前を入れるだけ** で使えます（アプリのインストールやアカウント登録は不要）。

## 1. できること

| 機能 | 内容 |
|---|---|
| 地図で現在地 | メンバーの位置を地図にマーカーで表示。地図は国土地理院（標準・淡色・航空写真）とOpenStreetMapを切り替えられます |
| 位置の送信 | アプリを開いている間は **30分ごとに自動送信**。地図下の **「📍 今の位置を送信」** でいつでも送れます |
| 圏外への対応 | 電波がないときに送った位置・チャットは端末に保存され、**電波が戻ると自動で送られます** |
| チャット | 文字のやり取り。送信待ちのメッセージは薄く表示されます |
| 写真の投稿 | 📷 ボタンで投稿。**自動で圧縮**（長辺1280px・最大およそ600KB）。写真に位置情報があればその地点、なければ最後に送った現在地を撮影地点として、地図に 📷 で表示します |
| GPXコース | メニューからGPXを読み込むと、コースを地図に表示し、各メンバーの **「何km地点」** と進み具合のバーを表示します。往復・周回コースでは、前回の地点に近い側を選びます |
| 状態の切り替え | 走行中／休憩中／要サポート／リタイア／ゴール。切り替えるとチャットに記録が残ります |
| 要サポート通知 | 「要サポート」を選ぶと **全員の画面に赤い通知が出て**（振動と音つき、対応する端末のみ）、地図のマーカーが点滅します。「地図で見る」でその人の位置に移動します |
| ルームコード | 大会ごとにコードを分けられます。同じコードの人だけが互いに見えます |
| その他 | 電池残量の表示（対応する端末のみ）、画面を消さない設定、招待リンクのコピー |

## 2. まず動きを見る（デモモード）

`public/js/firebase-config.js` を書き換える前は、自動で **デモモード** になります。
5人のダミーメンバーがコース上を進み、**参加から40秒後に「要サポート」通知の例** が流れます。データは端末の中だけで、どこにも保存されません。

ブラウザで `index.html` を直接開くと動きません（ブラウザの制限）。次のどちらかで開いてください。

- **パソコンで試す**：このフォルダでターミナルを開き、次を実行して、ブラウザで <http://localhost:8000> を開く
  ```bash
  python3 -m http.server 8000 -d public
  # または（Node.jsがある場合）
  npx serve public
  ```
- **公開してから試す**：手順3で公開したURLの末尾に `?demo=1` を付けると、設定後でもデモモードで開けます

## 3. Firebaseに登録して公開する

所要時間の目安は30分です。Googleアカウントが必要です。**クレジットカードの登録は不要**（無料のSparkプランのまま使えます）。

### 手順1：Firebaseプロジェクトを作る

1. <https://console.firebase.google.com/> を開き、「プロジェクトを作成」（または「Firebase プロジェクトを使ってみる」）
2. プロジェクト名を入力（例：`runners-live-club`）。この名前をもとにした **プロジェクトID** が公開URLの一部になります
3. Googleアナリティクスは **オフ** で問題ありません → 作成

### 手順2：Webアプリを登録し、設定をコピーする

1. プロジェクトのトップで **「</>」（ウェブ）** のアイコンを押す
2. アプリのニックネームを入力（例：`runners-live`）。「Firebase Hosting も設定する」のチェックは **不要** → 「アプリを登録」
3. 表示された `const firebaseConfig = { ... }` の中身を、`public/js/firebase-config.js` の同じ部分に **上書きで貼り付け** ます

   ```js
   export const firebaseConfig = {
     apiKey: 'AIza....',
     authDomain: 'runners-live-club.firebaseapp.com',
     projectId: 'runners-live-club',
     storageBucket: 'runners-live-club.appspot.com',   // ← 値が少し違っても問題ありません
     messagingSenderId: '1234567890',
     appId: '1:1234567890:web:abcdef...',
   };
   ```
   > `apiKey` は公開されても問題のない値です（パスワードではありません）。データは手順5のセキュリティルールで守ります。

   あとで確認するときは、左上の ⚙ →「プロジェクトの設定」→「マイアプリ」から見られます。

### 手順3：匿名ログインを有効にする

1. 左メニュー「構築」→ **Authentication** →「始める」
2. 「ログイン方法」タブ →「匿名」を選び → **有効にする** → 保存

> 匿名ログインにより、メンバーはアカウント登録なしで使えます。一方、ルールで「自分の情報は自分しか書き換えられない」ようにしています。

### 手順4：Firestore（データベース）を作る

1. 左メニュー「構築」→ **Firestore Database** →「データベースの作成」
2. ロケーション：**`asia-northeast1`（東京）** を推奨（あとから変更できません）
3. **「本番環境モードで開始する」** を選んで作成（ルールは手順5で正しいものに置き換えます）

> 写真もFirestoreに圧縮して保存するため、Cloud Storage（有料プランが必要）は使いません。

### 手順5：公開する（Firebase CLI）

パソコンに **Node.js**（<https://nodejs.org/> のLTS版）を入れてから、ターミナル（Windowsは「コマンドプロンプト」か「PowerShell」）で次を順に実行します。

```bash
# 1) Firebase CLI を入れる（初回のみ）
npm install -g firebase-tools

# 2) Googleアカウントでログイン（ブラウザが開きます）
firebase login

# 3) この README があるフォルダ（runners-live）に移動
cd runners-live

# 4) 使うプロジェクトを選ぶ（矢印キーで選んでEnter。別名は "default" と入力）
firebase use --add

# 5) セキュリティルールとアプリを公開
firebase deploy --only firestore:rules,hosting
```

最後に表示される **`Hosting URL: https://<プロジェクトID>.web.app`** が公開URLです。

> **`Hosting` のサイトが見つからない旨のエラーが出たとき**：Firebaseコンソールの左メニュー「構築」→ **Hosting** →「始める」を押し、表示される説明は「次へ」で最後まで進めてから（コマンドはすでに実行済みなので不要）、5) をもう一度実行してください。
> **コードを直したとき** も、5) のコマンドをもう一度実行すれば反映されます。
> **ルールだけをコンソールで貼りたい場合**：Firestore Database →「ルール」タブに `firestore.rules` の中身を貼り付けて「公開」でも同じです。

## 4. 公開後の最初の確認（2人で）

大会で使う前に、**2台のスマホ** で次を確認してください（この部分は開発環境からは実機で確かめられていません）。

- [ ] 2人とも同じルームコードで参加でき、メンバー一覧に2人が出る
- [ ] 初回に位置情報の許可を求められ、「許可」すると地図に自分のマーカーが出る
- [ ] 「📍 今の位置を送信」で、相手の画面の「位置 たった今」が更新される
- [ ] チャットが相手に届く
- [ ] 写真を投稿でき、相手が開くと高画質で見られ、「撮影地点を見る」で地図に移動する
- [ ] メニューからGPXを読み込むと、相手の画面にもコースと「○km地点」が出る
- [ ] 「要サポート」にすると、相手の画面に赤い通知が出てマーカーが点滅する（確認後「走行中」に戻す）
- [ ] 機内モードでチャットを送り、機内モードを解除すると相手に届く
- [ ] 確認が終わったらルームを退出し、テスト用データを削除する（[7. データの削除](#データの削除)）

**位置が取れないとき（iPhone）**：設定 → プライバシーとセキュリティ → 位置情報サービス → オン、さらに「Safari のWebサイト」→「使用中のみ」、「正確な位置情報」をオン。
**位置が取れないとき（Android）**：Chromeのアドレスバー左のアイコン → 権限 → 位置情報を許可。端末の「位置情報」もオンにする。

## 5. メンバーへの案内文（コピーして使えます）

アプリのメニュー（☰）→「招待リンクをコピー」で、ルームコード入りのリンクが作れます。

```
【ランナーズ・ライブ】当日の位置共有にご協力ください
▼リンクを開いて、名前を入れて「参加する」を押すだけです
https://<プロジェクトID>.web.app/?room=<ルームコード>

・位置情報の利用を聞かれたら「許可」してください
・エイドなど電波のある場所で「📍 今の位置を送信」を押してください
  （画面を消すと自動送信は止まります）
・体調不良などのときは状態を「要サポート」に。全員に通知が届きます
・ただし緊急時は、まず電話（110／119／大会本部）やLINEで連絡してください
```

## 6. 運用上の注意

- **画面を消すと送信が止まります。** Webアプリの仕組み上、スマホの画面を消したりブラウザを閉じたりすると、自動送信（30分ごと）は止まります。トレイルの山中では、**エイドなど電波のある場所で「📍 今の位置を送信」を押す運用** を前提にしてください。メニューの「画面を消さない」をオンにすると送り続けられますが、電池の消費が大きく増えます。
- **プッシュ通知はありません。** 「要サポート」の通知は、アプリを開いている人の画面にだけ出ます。**緊急時の連絡は電話やLINEを優先** してください。
- **圏外で押した送信は、電波が戻ったときに届きます。** そのため相手の画面の「位置 ○分前」は、実際にその場所にいた時刻（GPSを取った時刻）で表示しています。
- **「何km地点」はGPSとGPXからの推定です。** GPSの誤差（山間部では数十m〜100m以上）や、GPXの精度によってずれます。コースから200m以上離れているときは「コース外 約○m」と表示します。
- **地図のタイル**（国土地理院・OpenStreetMap）は表示のたびに通信します。電波の弱い場所では地図の背景が出ないことがありますが、マーカーやコースは表示されます。
- 推奨ブラウザ：iPhoneはSafari、AndroidはChrome（いずれも最新版）。LINEの中で開いた場合も動きますが、位置情報の許可が出ないときは「ブラウザで開く」を選んでください。

## 7. 費用・データ・安全性

### 費用の目安（無料のSparkプラン）

Sparkプランは上限を超えると **課金されずに止まる** だけで、請求は発生しません。主な無料枠は次のとおりです（作成時に把握していた値です。変更されることがあるので、最新は <https://firebase.google.com/pricing> で確認してください）。

| 項目 | 無料枠（1日あたり） | このアプリでの使い方 |
|---|---|---|
| Firestore 読み取り | 50,000回 | 誰かが位置を送るたびに、開いている全員に1回ずつ。チャットは開くたびに最大150件 |
| Firestore 書き込み | 20,000回 | 位置送信・発言・状態変更ごとに1回（写真は2回） |
| Firestore 保存容量 | 1 GiB | 写真1枚あたり最大およそ0.6MB |
| Hosting 転送量 | 約360MB | アプリ本体は約80KB（地図の背景は国土地理院などから直接取るので含まれません） |

**目安**：20人が10時間、30分ごとに位置を送り、全員が画面を開いたままの場合でも、読み取りはおよそ8,000〜10,000回です。これにチャットと写真を加えても、1大会なら無料枠に収まる見込みです。ただし **写真の容量（保存1GiB）は大会ごとに削除する** のがおすすめです。
※この数値は計算上の目安で、実際の大会での測定はしていません。Firebaseコンソールの「使用量と請求額」で実際の量を確認できます。

### データの削除

大会後は、Firebaseコンソール → Firestore Database →「データ」タブで `rooms` → 該当のルームコードを開き、`members`／`messages`／`photos`／`meta` の各コレクションの「︙」→「コレクションを削除」で削除できます。`rooms` コレクションごと削除すれば、すべてのルームが消えます。

### 安全性について（大事なところ）

- **ルームコードが合言葉です。** 公開URLとルームコードを知っている人は、そのルームの位置・チャット・写真を見られます。`trail-k3x9q` のように **推測されにくいコード** を使い（参加画面の「自動生成」が使えます）、**大会ごとに変えて**、終わったらデータを削除してください。
- ルーム一覧を取得する方法はないため、コードを知らない人がルームを見つけることはできません。
- セキュリティルール（`firestore.rules`）で次を守っています：ログイン（匿名）していない人は読み書きできない／自分のメンバー情報と投稿しか書き換え・削除できない／他人になりすました投稿はできない／決められた項目と長さ以外は保存できない。
- 自宅周辺など、知られたくない場所では位置を送らないよう、メンバーに伝えてください（自動送信はアプリを開いている間だけです。大会後はルームを退出してください）。
- さらに不正利用を防ぎたい場合は、Firebaseの **App Check**（reCAPTCHA）を追加できます（このアプリには未実装）。

## 8. 設定の変更・開発者向け情報

### よく変える設定（`public/js/firebase-config.js`）

| 項目 | 初期値 | 内容 |
|---|---|---|
| `AUTO_SEND_MINUTES` | 30 | 位置の自動送信間隔（分） |
| `STALE_MINUTES` | 60 | この時間以上更新のないメンバーのマーカーを薄く表示 |

### ファイル構成

```
runners-live/
├── README.md               この手順書
├── firebase.json           Firebase Hosting / Firestore の設定
├── firestore.rules         セキュリティルール
├── sample/
│   └── sample-course.gpx   動作確認用のGPX（高尾〜陣馬 付近の参考線。実際の登山道ではありません）
└── public/                 公開されるファイル
    ├── index.html
    ├── css/style.css
    └── js/
        ├── app.js              画面と動作
        ├── firebase-config.js  Firebaseの設定（★ここを書き換える）
        ├── backend-firebase.js Firebaseとのやり取り
        ├── backend-demo.js     デモモード
        ├── demo-course.js      デモ用コース
        ├── geo.js              GPX読み込み・距離計算
        └── photo.js            写真の圧縮・位置情報の読み取り
```

### データの構成（Firestore）

```
rooms/{ルームコード}/members/{ユーザーID}  名前・色・状態・緯度経度・精度・測位時刻・km・電池
rooms/{ルームコード}/messages/{ID}        チャット（text / photo / alert / system）。写真は縮小版のみ
rooms/{ルームコード}/photos/{ID}          写真の本体（圧縮済みJPEG）。開いたときだけ読み込む
rooms/{ルームコード}/meta/course          GPXコース（間引き後の座標）
```

### 使っているもの

- 地図：[Leaflet](https://leafletjs.com/) 1.9.4（unpkg から読み込み）
- 地図の背景：[地理院タイル](https://maps.gsi.go.jp/development/ichiran.html)、[OpenStreetMap](https://www.openstreetmap.org/copyright)
- Firebase JavaScript SDK 10.12.2（gstatic から読み込み）。ビルド作業は不要です

### ローカルでFirebaseエミュレーターを使って試す

```bash
# runners-live フォルダで（Java 11以上が必要）
firebase emulators:start --only auth,firestore --project demo-runners
# 別のターミナルで
python3 -m http.server 8000 -d public
```

`firebase-config.js` の `apiKey` を任意の文字列（例 `fake-api-key`）、`projectId` を `demo-runners` にして、
<http://localhost:8000/?emulator=1> を開くとエミュレーターにつながります（`?emulator=1` は localhost でのみ有効）。

## 9. 確認できたこと・できていないこと

**確認済み（開発環境で、自動テストにより確認）**
- デモモード：スマホ幅（390px）とPC幅（1366px）の表示・横スクロールが出ないこと、チャット送信、写真の圧縮と投稿（3000×2000の写真を約120KBに圧縮）、写真の位置情報（EXIF）の読み取り、メンバー一覧、GPXの読み込みとコース上の距離計算、「要サポート」の通知とマーカーの点滅
- Firebaseエミュレーター上で2人同時に接続：互いの位置・km地点の表示、チャット・写真（高画質版の読み込みを含む）・GPXコースの共有、「要サポート」通知の受信、**オフラインで送ったメッセージが再接続後に届くこと**、退出で一覧から消えること
- セキュリティルール：他人の情報の書き換え、なりすまし投稿、不正な状態値・項目の追加、写真の一覧取得、不正なルームコードを **すべて拒否** し、自分の情報の更新は許可されること

**未確認（この環境からは確かめられないもの）**
- 本物のFirebaseプロジェクトへの接続と公開（エミュレーターと本番の違いによる問題が出る可能性があります）
- 実機スマホでのGPS取得・位置情報の許可の流れ・振動・通知音（iPhone／Androidそれぞれ）
- 山間部など電波の弱い場所での実際の動き、電池の消費量

→ 公開後、まず [4. の手順](#4-公開後の最初の確認2人で) で2人で試してください。

### 次の段階の候補

クラブで1回試したあと、**画面を消しても位置を記録・送信できるネイティブアプリ化**（バックグラウンドでの位置取得とプッシュ通知）を検討するのが自然な流れです。データの形はそのまま使えるように作っています。
